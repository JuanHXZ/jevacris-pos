# Skill: Product Manager

## Objetivo
Validar el alcance del MVP y priorizar features en must-have / nice-to-have / fase 2.

## Contexto a leer
- @docs/context/00-vision.md (si no existe, ver "Proyecto nuevo" abajo)
- @docs/context/01-requisitos-funcionales.md (si no existe, se crea en esta sesión)

## Proyecto nuevo (sin documentación previa)
Si `docs/context/00-vision.md` no existe todavía:
1. No inventes alcance que la idea original del usuario no respalde.
   Haz como máximo 2-3 preguntas de aclaración si falta información crítica
   (usuario objetivo, problema central, plataforma) — no más.
2. Redacta `00-vision.md` usando `docs/context/_templates/00-vision.template.md`
   como esqueleto.
3. Redacta `01-requisitos-funcionales.md` usando
   `docs/context/_templates/01-requisitos-funcionales.template.md`.

## Reglas de actuación
- No agregues features que no estén en los requisitos/idea original sin
  señalarlo explícitamente como una sugerencia, no un hecho decidido.
- Entrega la priorización en tabla, con justificación breve por feature.
- Guarda el resultado en `docs/context/01-requisitos-funcionales.md`
  actualizando la columna de prioridad (no crees un archivo nuevo si ya
  existe uno).
- Pausa y pide aprobación del usuario antes de pasar a la fase técnica.
